# K230 多功能AI视觉检测 - 开发踩坑与解决方案

## 1. ST7701 屏幕横屏模式下视频撕裂/漂移/色偏

### 现象
使用 `Display.show_image()` 将摄像头画面显示到 OSD 层时，画面出现严重撕裂、漂移和颜色偏差。启动初始化阶段也有约 2 秒的撕裂预览。

### 根本原因
ST7701 屏幕物理分辨率是 **480×640（竖屏）**，我们在 **640×480（横屏）** 模式下使用，显示时需要旋转：

| 显示方式 | 旋转处理 | 结果 |
|---------|---------|------|
| VIDEO 层 (`bind_layer`) | **硬件旋转** | 帧率不降，无撕裂 |
| OSD 层 (`show_image`) | **软件旋转** | 帧率降低，撕裂+漂移 |

来源：[Kendryte 官方 BUG 反馈](https://www.kendryte.com/answer/questions/10010000000001826)

### 解决方案
摄像头画面必须绑定到 **VIDEO 层**（硬件旋转），不要用 `sensor.snapshot()` + `Display.show_image()` 到 OSD 层：

```python
# 正确：绑定 VIDEO 层，硬件旋转无撕裂
sensor_bind_info = self.pl.sensor.bind_info(x=0, y=0, chn=CAM_CHN_ID_0)
Display.bind_layer(**sensor_bind_info, layer=Display.LAYER_VIDEO1)

# 错误：OSD 层软件旋转，会撕裂
img = self.pl.sensor.snapshot(chn=CAM_CHN_ID_1)
Display.show_image(img, 0, 0, Display.LAYER_OSD3)
```

退出摄像头模式时解绑：
```python
Display.unbind_layer(Display.LAYER_VIDEO1)
```

### 经验
- K230 的 VIDEO 层支持硬件旋转，OSD 层不支持
- 任何需要实时显示摄像头画面的场景，优先使用 VIDEO 层绑定
- OSD 层只用于叠加静态 UI 元素（按钮、文字等）

## 2. LVGL flush 回调与 OSD 层冲突

### 现象
在子线程中用 `Display.show_image()` 写 OSD3 层显示摄像头画面时，画面撕裂且颜色异常。

### 根本原因
LVGL 的 `disp_drv_flush_cb` 回调默认将渲染结果写到 **LAYER_OSD3**：

```python
def disp_drv_flush_cb(disp_drv, area, color):
    if disp_drv.flush_is_last() == True:
        Display.show_image(disp_img1)  # 默认写到 OSD3
```

如果同时在子线程写 OSD3 显示摄像头，两个线程同时操作同一层 → 画面撕裂。

### 解决方案
摄像头显示循环必须在**主线程阻塞运行**，这样 `lv.task_handler()` 不会被调用，LVGL 不会刷新 OSD3：

```python
def initialize(self):
    # ... 初始化 ...
    self._camera_loop()       # 主线程阻塞
    self.app_manager.go_home()  # 退出后返回主界面
```

### 经验
- K230 的 LVGL 和 Display.show_image() 共享 OSD3 层
- 不要在子线程中同时操作 Display 的同一层
- 阻塞式摄像头循环是 K230 的标准模式（参考原版 camera app）

## 3. 启动时 VIDEO1 层显示撕裂预览

### 现象
Pipeline 初始化后、LVGL 主界面加载前，屏幕显示约 2 秒撕裂的摄像头画面。

### 根本原因
Pipeline.create() 中将 sensor CHN0 绑定到 VIDEO1 层，sensor 启动后立即输出画面，但此时传感器尚未稳定，导致撕裂。

### 解决方案
Pipeline 初始化时保持 VIDEO1 绑定（主界面 LVGL 会覆盖），不要提前解绑。进入摄像头应用时重新绑定 VIDEO1，退出时解绑。

### 经验
- Pipeline 初始化时 VIDEO1 绑定是正常的，LVGL 的 OSD 层会在上面覆盖
- 不要在 display_init 后立即 `Display.unbind_layer(Display.LAYER_VIDEO1)`，这会导致后续摄像头应用无法正常绑定

## 4. LVGL 白色背景覆盖视频层

### 现象
尝试让 LVGL 屏幕透明以显示 VIDEO 层的摄像头画面，但始终显示白色背景。

### 根本原因
LVGL 的 `lv.obj()` 默认白色不透明背景，`set_style_bg_opa(0)` 在 K230 的 MicroPython LVGL 绑定中无法让屏幕真正透明。

### 解决方案
不要尝试让 LVGL 透明来显示视频层。正确做法是：
1. 摄像头画面绑定到 VIDEO 层（自动显示在 LVGL 下方）
2. UI 元素用 OSD 图层叠加（`Display.show_image()` 到 LAYER_OSD0）
3. 完全绕过 LVGL，用 OSD 绘图 API 画 UI

```python
ui_img = image.Image(640, 480, image.RGB565)
ui_img.draw_rectangle(...)   # 画标题栏
ui_img.draw_string_advanced(...)  # 画文字
Display.show_image(ui_img, 0, 0, Display.LAYER_OSD0)
```

### 经验
- K230 的显示层级从下到上：VIDEO1 → OSD3 → OSD2 → OSD1 → OSD0 → LVGL
- LVGL 无法做到真正的透明穿透
- 需要显示摄像头的应用应完全绕过 LVGL，使用 OSD 图层系统

## 5. AttributeError: 'AppManager' object has no attribute 'text_config'

### 现象
启动时报错 `AttributeError: 'AppManager' object has no attribute 'text_config'`

### 根本原因
AppManager 类的 `__init__` 中没有初始化 `self.text_config` 属性，但 BaseApp 的构造函数中访问了 `self.app_manager.text_config`。

### 解决方案
在 AppManager.__init__ 中添加：
```python
self.text_config = None
```

### 经验
- BaseApp 依赖 AppManager 的多个属性（config, text_config, pl, font_16 等）
- 创建 AppManager 时必须确保所有 BaseApp 需要的属性都已初始化

## 6. NameError: name 'load_boot_seq' isn't defined

### 现象
picture_get 应用启动时报错 `NameError: name 'load_boot_seq' isn't defined`

### 根本原因
使用通配符导入 `from apps.picture_get.core import *`，但模块中的函数名以 `_` 开头（如 `_load_boot_seq`），Python 的通配符导入不包含以 `_` 开头的名称。

### 解决方案
改为显式导入：
```python
from apps.picture_get.core import save_photo, ensure_dir, _load_boot_seq, _save_boot_seq, _load_seq, _save_seq, SAVE_BASE
```

### 经验
- 避免使用 `from module import *`
- 以 `_` 开头的函数/变量不会被通配符导入
- 始终使用显式导入，明确依赖关系

## 7. machine.Timer 与 LVGL 冲突导致输入状态不更新

### 现象
io_tester 应用中输入状态标签始终显示"高电平"，不随实际 IO 状态变化。

### 根本原因
使用 `machine.Timer` 硬件定时器回调中更新 LVGL 控件，与 LVGL 的事件循环冲突。MicroPython 的硬件定时器回调在中断上下文中执行，不能安全地调用 LVGL API。

### 解决方案
改用 LVGL 的定时器：
```python
# 错误：硬件定时器回调中更新 LVGL 控件
self._hw_timer = Timer(-1)
self._hw_timer.init(period=300, mode=Timer.PERIODIC, callback=self._timer_update)

# 正确：LVGL 定时器
self._lv_timer = lv.timer_create(self._timer_update, 300, None)
```

### 经验
- K230 MicroPython 中，硬件定时器回调不能安全操作 LVGL 控件
- 必须使用 `lv.timer_create()` 在 LVGL 事件循环中更新 UI
- 删除 LVGL 定时器用 `timer._del()`，不是 `lv.timer_delete()`（该 API 不存在）

## 8. lv.timer_delete 不存在

### 现象
调用 `lv.timer_delete(timer)` 报错 `AttributeError: 'module' object has no attribute 'timer_delete'`

### 根本原因
K230 的 MicroPython LVGL 绑定中，删除定时器的方法是 `timer._del()`，不是 `lv.timer_delete()`。

### 解决方案
```python
# 错误
lv.timer_delete(self._lv_timer)

# 正确
self._lv_timer._del()
```

### 经验
- K230 的 LVGL MicroPython 绑定与标准 LVGL Python 绑定有差异
- 遇到 API 不存在时，检查对象是否有 `_del()` 方法

## 9. BaseApp.launch() 中 lv.scr_load 时序问题

### 现象
摄像头应用退出后，`go_home()` 加载主界面，但 `launch()` 中的 `lv.scr_load(self.screen)` 又覆盖了主界面。

### 根本原因
原版 `BaseApp.launch()` 在 `initialize()` 之后调用 `lv.scr_load(self.screen)`。如果 `initialize()` 阻塞运行摄像头循环并已调用 `go_home()`，后续的 `lv.scr_load` 会覆盖主界面。

### 解决方案
重写 `launch()` 方法，在 `initialize()` 之前加载屏幕：
```python
def launch(self):
    self.screen = lv.obj()
    self.screen.set_style_text_font(self.app_manager.font_16, 0)
    self._create_title_bar()
    self.model_dialog = ModalDialog(self.screen, font_16=self.app_manager.font_16)
    lv.scr_load(self.screen)   # 先加载屏幕
    self.initialize()           # 再初始化（可能阻塞）
```

### 经验
- 阻塞式应用需要重写 `launch()` 控制加载时序
- `initialize()` 阻塞结束后自行调用 `go_home()`，不需要 BaseApp 的后续逻辑

## 10. 触摸事件处理：LVGL vs TOUCH 设备

### 现象
OSD 模式下 LVGL 按钮无法响应触摸。

### 根本原因
摄像头应用使用 OSD 图层系统绕过 LVGL，LVGL 的触摸输入系统不工作。需要直接读取 TOUCH 设备。

### 解决方案
```python
from machine import TOUCH
tp = TOUCH(0)

# 在循环中读取触摸
point = tp.read(1)
if len(point):
    pt = point[0]
    if pt.event == TOUCH.EVENT_DOWN:
        # 处理触摸事件
```

### 经验
- 使用 OSD 图层系统时，LVGL 的输入系统不工作
- 必须直接读取 TOUCH 设备处理触摸
- 触摸事件类型：`TOUCH.EVENT_DOWN = 2`, `TOUCH.EVENT_UP = 3`
- 触摸坐标是屏幕绝对坐标，需要手动判断是否在按钮区域内

## 11. OSD 图层 RGB565 色键透明

### 现象
OSD0 层的 RGB565 图像中，黑色区域 `(0,0,0)` 会变成透明，露出下方的 VIDEO 层。

### 根本原因
K230 的 OSD 层对 RGB565 格式使用色键透明：纯黑 `(0,0,0)` 被视为透明色。这是硬件行为。

### 解决方案
- 利用这个特性：UI 元素画在非黑色背景上，黑色区域自然透明显示摄像头
- 需要不透明的区域使用接近黑色但不为纯黑的颜色，如 `(1,1,1)` 或 `(17,7,4)`

```python
# 标题栏用深色但不纯黑，确保不透明
ui_img.draw_rectangle(0, 0, 640, 60, color=(17, 7, 4), thickness=1, fill=True)
```

### 经验
- RGB565 OSD 层的纯黑 `(0,0,0)` = 透明
- 需要不透明的深色区域使用 `(1,1,1)` 或更深但非零的颜色
- ARGB8888 格式的 OSD 层（如 Pipeline 的 osd_img）通过 alpha 通道控制透明度，不受此限制

## 12. 应用白名单过滤

### 现象
加载不兼容的应用导致启动失败或运行时崩溃。

### 解决方案
在 AppManager.scan_apps() 中添加白名单过滤：
```python
allowed_apps = ["taping_checker", "picture_get", "io_tester"]
app_dirs = [d for d in app_dirs if d in allowed_apps]
```

### 经验
- 只加载已测试兼容的应用
- 新应用开发完成后添加到白名单
- 避免加载未适配 BaseApp 架构的旧应用

## K230 显示层级参考

从下到上的层级顺序：

| 层级 | 用途 | 旋转支持 |
|------|------|---------|
| LAYER_VIDEO1 | 摄像头画面（sensor 绑定） | 硬件旋转 |
| LAYER_OSD3 | Pipeline osd_img / LVGL flush | 无 |
| LAYER_OSD2 | 备用 OSD 层 | 无 |
| LAYER_OSD1 | 备用 OSD 层 | 无 |
| LAYER_OSD0 | UI 叠加层 | 无 |

初始化时 `osd_layer_num=4` 启用全部 4 个 OSD 层。

## 摄像头应用开发模板

```python
def _camera_loop(self):
    # 1. 绑定 VIDEO 层（硬件旋转，无撕裂）
    sensor_bind_info = self.pl.sensor.bind_info(x=0, y=0, chn=CAM_CHN_ID_0)
    Display.bind_layer(**sensor_bind_info, layer=Display.LAYER_VIDEO1)

    # 2. 创建 OSD0 叠加层（UI 元素）
    ui_img = image.Image(640, 480, image.RGB565)
    self._draw_ui_overlay(ui_img)
    Display.show_image(ui_img, 0, 0, Display.LAYER_OSD0)

    # 3. 主循环（阻塞，不调用 lv.task_handler）
    while self.is_running:
        # 读取触摸
        if tp:
            point = tp.read(1)
            # ... 处理触摸 ...
        time.sleep_ms(10)

    # 4. 清理
    Display.unbind_layer(Display.LAYER_VIDEO1)
    clr = image.Image(640, 480, image.RGB565)
    clr.clear()
    Display.show_image(clr, 0, 0, Display.LAYER_OSD0)
```
